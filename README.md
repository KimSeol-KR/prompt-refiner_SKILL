# prompt-refiner

**대충 쓴 요청을 그대로 실행하지 않는 스킬.**

"이거 정리 좀 해줘"라고 쓴 사람의 머릿속에는 이미 받는 사람, 마감, 분량, 강조할 부분이 다 들어 있습니다.
안 적었을 뿐입니다. 이 스킬은 그 빠진 맥락을 **최소한의 마찰로** 끌어내고, 나머지는 합리적으로 채운 뒤 눈으로 확인시켜 줍니다.

```
이렇게 이해했어요 — 맞으면 진행할게요.

**하려는 것**: 회의록 3개를 하나의 보고 문서로 합치기
**만들 것**: A4 한 장, 결정사항 먼저 / 논의 내용 뒤
**이렇게 가정했어요**: 회의 순서대로 정리했고, 결론이 안 난 안건도 "미정"으로 남겨둘게요

확인하고 싶은 것:
1. 이 문서 어디에 쓰세요?
   A) 팀장님 보고 — 결정사항과 다음 할 일 위주로 압축
   B) 팀 공유 — 논의 맥락까지 남겨서 나중에 찾아보기 좋게
   C) 나만 볼 정리 — 형식 신경 안 쓰고 내용 위주로

"그냥 진행"이라고 하시면 위 가정대로 바로 만들게요.
```

---

## 무엇이 다른가

이런 도구는 대개 두 가지 중 하나로 실패합니다. 이 스킬은 그 둘을 동시에 피하는 데 설계를 다 씁니다.

| 흔한 실패 | 이 스킬의 대응 |
|---|---|
| **넘겨짚기** — 확인 없이 실행 → 원치 않은 결과물 → 재작업 | 결과가 갈리는 결손이 있으면 실행 전에 확인 |
| **질문 폭탄** — "독자는? 분량은? 톤은? 형식은?" → 사용자가 지침 | **질문 최대 2개**, 나머지는 기본값으로 채우고 카드에 적음 |

그리고 세 가지 장치가 마찰을 낮춥니다.

- **선택지로 묻습니다.** "형식은 어떻게 할까요?"에는 답을 못 해도 "표로 vs 줄글로"에는 누구나 답합니다.
- **"그냥 진행" 탈출구가 항상 있습니다.** 질문에 답하기 싫은 사용자가 막히지 않습니다.
- **묻기 전에 먼저 찾습니다.** 연결된 폴더·첨부·이전 대화·문서 커넥터를 훑고, 못 찾았으면 그 이유를 밝힙니다.

**과민 반응을 막는 것도 같은 비중으로 설계했습니다.** 이미 구체적인 요청, 단순 사실 질문, 결과물이 가벼운 일에는 카드를 띄우지 않습니다.

```
"temp.log 지워줘"           →  카드 없음. 그냥 지웁니다
"안 쓰는 파일들 좀 정리해줘"  →  카드 + 질문 2개. 원본 처리 확인
```

같은 삭제 요청인데 갈립니다. 기준은 "되돌릴 수 있느냐"가 아니라 **"의도가 덜 채워졌느냐"**입니다.

---

## 이 스킬이 하지 않는 일

대상은 **사용자가 쓴 요청문 하나**이고, 하는 일은 **거기 안 적힌 의도를 복원하는 것**입니다.

- 산출물을 더 좋게 만드는 것이 아닙니다 — 좋은 글쓰기·코딩 규범은 들어 있지 않습니다
- 안전장치가 아닙니다 — 되돌릴 수 없는 작업이라도 의도가 선명하면 묻지 않습니다
- 프롬프트 쓰는 법을 가르치지 않습니다 — 다음에도 대충 써도 되게 만드는 게 목표입니다

## 설치

### Claude Code — 플러그인으로 (권장)

```bash
claude plugin marketplace add KimSeol-KR/prompt-refiner_SKILL
claude plugin install prompt-refiner@kimseol-skills
```

비공개 저장소이므로 `gh auth login` 등으로 GitHub 인증이 되어 있어야 합니다.
업데이트는 `claude plugin marketplace update kimseol-skills`.

### claude.ai · Cowork — 스킬 업로드

1. [`dist/prompt-refiner.zip`](dist/prompt-refiner.zip) 을 내려받습니다
2. **Customize → Skills → + → Create skill → Upload a skill**
3. 받은 zip을 그대로 올립니다

### 직접 복사

```bash
cp -r plugins/prompt-refiner/skills/prompt-refiner  <프로젝트>/.claude/skills/
```

프로젝트 단위로 쓰려면 이 방법이 가장 단순합니다.

```

plugins/prompt-refiner/

      └── references/
          ├── gap-types.md               결손 7유형 · 탐지 신호 · 복원 질문
```

`SKILL.md`만 항상 읽히고, `references/`는 필요할 때만 열립니다.

## 검증 상태

케이스 6건으로 스킬 유무를 비교했습니다.

| | 스킬 있음 | 없음 |
|---|---|---|
| 통과율 | 29/29 | 13/29 |

스킬이 없을 때 실패가 두 갈래로 갈렸습니다 — 회의록 건은 **확인 없이 실행한 뒤 질문 4개**를, 홍보글 건은 **질문 5묶음을 한 번에** 던졌습니다. 막으려던 '넘겨짚기'와 '질문 폭탄'이 그대로 재현됐습니다.

트리거(스킬이 실제로 켜지는가)는 별도로 5건 측정해 5/5였습니다. 모호한 요청에는 걸리고, 단순 질문과 이미 구체적인 요청에는 걸리지 않았습니다.

**다만 이 숫자를 절대값으로 읽지 마세요.** 케이스를 만든 사람과 채점 기준을 정한 사람이 같고, 케이스당 실행이 1회입니다. 스킬 없는 쪽과의 *차이*만 신호로 보시고, 실사용 데이터는 아직 없습니다.

자세한 내역은 [CHANGELOG.md](CHANGELOG.md)에 있습니다 — 되돌린 수정과 효과가 없던 수정도 함께 적어뒀습니다.
