# 결손 7유형 — 무엇이 빠졌는지 알아내는 법

모호한 요청은 대체로 아래 7가지 중 하나 이상이 빠져 있다.
순서는 **결과물을 뒤흔드는 정도** 순이다. 위쪽이 빠졌으면 물어볼 값어치가 크고, 아래쪽은 대체로 기본값으로 메워도 된다.

---

## 1. 목적 (왜 필요한가) — 가장 비싼 결손

이걸 알면 아래 6개가 대부분 자동으로 정해진다. 하나만 물을 수 있으면 이것.

**탐지 신호**: 요청에 동사만 있고 쓰임새가 없음. "정리해줘", "만들어줘", "찾아줘"

**복원 질문**
- "이거 만들어서 어디에 쓰실 거예요? (보고 / 나중에 나만 다시 볼 용도 / 남한테 보낼 것)"
- "이걸 받아보는 사람이 그다음에 뭘 하게 되나요?"

**목적이 바꾸는 것**: 분량, 말투, 어디까지 설명할지, 무엇을 앞에 둘지 — 거의 전부

---

## 2. 판단 기준 (뭐가 좋은 건가)

"좋은 걸로", "괜찮게", "제대로"는 사용자 머릿속에만 있는 기준을 가리키는 말이다.

**탐지 신호**: 평가·선택·추천을 시키는데 기준이 없음. "좋은 거 골라줘", "잘 써줘", "최적화해줘"

**복원 질문**
- "고를 때 뭐가 제일 중요해요? (싼 것 / 빠른 것 / 안전한 것)"
- "'잘 된' 결과는 어떤 모습일까요? 반대로 이러면 실패다 싶은 건요?"

**요령**: 성공 조건보다 **실패 조건**을 묻는 게 답을 얻기 쉽다. "이러면 안 된다"는 누구나 바로 말한다.

---

## 3. 대상 재료 (무엇을 가지고)

지시대명사만 있고 실물이 없는 경우. 사용자는 자기가 보고 있는 화면을 상대도 본다고 착각한다.

**탐지 신호**: "그거", "이 파일", "저번에 그", "여기 있는 거" / 첨부는 없는데 첨부를 전제한 말투

**복원 질문**
- "어떤 파일/글을 말씀하시는 건지 붙여 주시거나 이름을 알려주세요."
- 후보를 찾을 수 있으면 묻지 말고 찾아서 짚는다: "Downloads의 `매출_최종.xlsx` 말씀이시죠?"

**요령**: 이건 질문 개수 제한의 예외다. 재료가 없으면 아예 시작을 못 하므로 반드시 확보한다.

**순서가 중요하다.** 질문 목록을 만들기 **전에** 연결된 폴더·첨부·이전 대화를 먼저 훑는다. 물어보기로 정한 뒤에 훑으면 이미 늦었고, 사용자에게는 "찾아보지도 않고 물었다"로 보인다.
찾았으면 확인만 받고("이 파일 말씀이시죠?"), 못 찾았으면 **못 찾은 이유를 한 줄 덧붙여** 묻는다("폴더 연결이 안 돼 있어서 파일을 못 봅니다").

재료를 끝내 확보 못 했으면 확인 카드를 쓰지 말고 질문만 던진다. 대상을 못 본 채로 "만들 것"과 "가정"을 쓰면 지어낸 소리가 되기 때문이다. 가정은 결과물을 만든 뒤에 붙인다.

---

## 4. 산출물 형태 (어떤 모양으로)

**탐지 신호**: 형태 언급 없음. 또는 "정리"처럼 형태를 뜻하는 것 같지만 아무 형태도 지정하지 않은 말

**복원 질문**
- "어떤 형태가 편하세요? (표 / 줄글 / 목록 / 파일로 받기)"
- "그대로 어디에 붙여 넣으실 건가요?" ← 붙여 넣을 곳을 알면 형태가 정해진다

**기본값으로 메워도 되는 경우가 많다** — `defaults.md` 참조

---

## 5. 범위·분량 (어디까지)

**탐지 신호**: "간단하게", "자세히", "전부", "좀" — 사람마다 3배씩 차이 나는 말들

**복원 질문**
- "간단하게는 어느 정도일까요? (3줄 / 반 장 / 한 장)"
- "전체 다 볼까요, 아니면 최근 것만 볼까요?"

**요령**: "간단히"는 요청자마다 편차가 가장 큰 단어다. 숫자로 바꿔서 되물으면 마찰 없이 정해진다.

---

## 6. 독자·말투 (누가 읽나)

**탐지 신호**: 남에게 보여줄 글인데 받는 사람이 없음

**복원 질문**
- "누가 읽나요? (나만 / 팀 / 상사 / 고객)"

**요령**: 목적을 이미 물었으면 독자는 대개 따라 나온다. 따로 묻지 말 것.

---

## 7. 제약 (하면 안 되는 것)

**탐지 신호**: 기존 것을 고치는 작업 / 기술 스택·양식·규정이 걸린 작업

**복원 질문**
- "건드리면 안 되는 부분이 있을까요?"
- "원본은 남겨둘까요, 덮어쓸까요?" ← 원문에 안 적혀 있고 되돌릴 수 없는 작업이면 이건 확인한다. 이미 "덮어써도 돼"라고 적혀 있으면 묻지 않는다.

---

## 우선순위 정하는 법

공백이 여러 개면 이 순서로 자른다.

1. **재료(3번)가 없으면 그것부터.** 나머지는 재료를 봐야 판단이 선다.
2. **제약(7번)에 결손이 있고 되돌릴 수 없는 작업이면 반드시 확인.** 질문 2개 제한과 무관하게 확인한다. 단 제약이 이미 선명하면(무엇을 지울지, 어디까지인지 원문에 있음) 묻지 않는다 — 되돌릴 수 없다는 사실만으로는 확인 사유가 아니다.
3. **나머지 중 목적(1번) 또는 판단 기준(2번) 하나.** 이 둘은 아랫줄 4~6번을 대부분 결정한다.
4. **4~6번은 기본값으로 채우고 카드에 적는다.** 이걸 묻기 시작하면 질문 폭탄이 된다.

---

## 결손이 아닌 것

아래는 빠져 있어도 묻지 않는다. 물으면 사용자가 "그걸 내가 어떻게 알아"라고 느낀다.

- 사용자가 몰라야 정상인 것 (어떤 라이브러리를 쓸지, 어떤 알고리즘을 쓸지)
- 만들어 놓고 물으면 될 것 (색상, 문구 다듬기, 정렬 순서)
- 결과를 보면 사용자가 바로 판단할 수 있는 것

즉 **"지금 답을 들어야만 방향이 갈리는 것"만 결손이다.** 나머지는 만든 뒤에 고치는 게 서로 빠르다.
