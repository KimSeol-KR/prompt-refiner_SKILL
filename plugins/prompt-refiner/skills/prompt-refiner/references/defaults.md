# 기본값 사전 — 안 물어보고 채우는 값들

빠진 정보 전부를 물으면 사용자가 지친다. 아래 기본값으로 채우고, 채운 것을 **확인 카드에 한 줄로 적어** 사용자가 틀렸을 때 바로 잡을 수 있게 한다.

**여기 있는 값은 "이렇게 하는 게 좋다"가 아니다.** 그건 이 스킬의 일이 아니다 — 좋은 글쓰기나 좋은 코딩을 가르치는 게 아니라, 사용자가 안 적은 칸을 의도에서 가장 덜 벗어나게 메우는 것이 일이다.

그래서 기본값을 고르는 근거는 둘뿐이다.

1. **사용자가 그 칸을 채웠다면 이렇게 말했을 가능성이 높은가** — 원문에서 읽히는 것
2. **틀렸을 때 되돌리기 쉬운가** — 짧은 걸 늘리는 건 쉽고 긴 걸 줄이는 건 아깝다. 원본을 남긴 걸 지우는 건 쉽고 덮어쓴 걸 되살리는 건 불가능하다

둘 중 어느 쪽으로도 정당화되지 않는 값은 **기본값이 아니라 훈수다.** 넣지 않는다.

## 글쓰기 (보고서·메일·공지·기획서)

| 항목 | 기본값 | 이유 |
|---|---|---|
| 분량 | A4 한 장 이내 | 짧은 걸 늘리는 게 반대보다 쉽다 |
| 말투 | 사용자가 요청에서 쓴 말투를 그대로 | 사용자 문체가 곧 사용자 기준 |
| 구조 | 원문에서 사용자가 먼저 꺼낸 것을 먼저 | 사용자가 앞에 쓴 것이 사용자가 중요하게 본 것이다 |
| 독자 | 사정을 모르는 동료 한 명 | 과하지도 부족하지도 않은 설명 수준 |
| 형태 | 대화창에 바로 (파일 요청이 있을 때만 파일) | 파일은 사용자가 한 번 더 열어야 함 |

**예외**: 사용자가 "메일", "공지"처럼 매체를 지정했으면 그 매체의 관행을 따른다 (메일이면 제목 + 인사 + 본문 + 맺음).

## 조사·검색

| 항목 | 기본값 | 이유 |
|---|---|---|
| 최신성 | 최근 것 우선, 날짜 표기 | 오래된 정보가 섞이면 사용자가 구분 못 함 |
| 출처 | 항상 링크로 표기 | 사용자가 직접 확인할 수 있어야 함 |
| 깊이 | 요약 먼저, 상세는 아래 | 필요한 만큼만 읽고 멈출 수 있음 |
| 관점 | 원문에 결론이 안 적혀 있으면 한쪽으로 몰지 않는다 | 사용자가 답을 정해두지 않은 것을 대신 정하면 그건 의도가 아니라 내 판단이다 |
| 분량 | 핵심 3~5개 | 그 이상은 사용자가 다시 정리해야 함 |

## 코딩·수정

| 항목 | 기본값 | 이유 |
|---|---|---|
| 변경 폭 | 요청한 부분만 최소 수정 | 리팩터링은 사용자가 확인해야 할 면적을 늘린다 |
| 스택 | 이미 쓰는 것 유지 | 사용자가 바꿔달라고 안 했으면 바꾸지 말라는 뜻이다 |
| 원본 | 남긴다 (덮어쓰기는 확인 후) | 되돌릴 수 없는 작업 |
| 설명 | 뭘 바꿨는지 한 줄 요약 | 사용자가 의도와 다른지 판단하려면 무엇이 바뀌었는지 알아야 한다 |
| 주석 | 사용자 코드 주석 스타일 유지 | 사용자 표기가 곧 사용자 기준 — 용어 유지와 같은 규칙이다 |

## 정리·요약

| 항목 | 기본값 | 이유 |
|---|---|---|
| 순서 | 원문 순서 유지 | 사용자가 원문과 대조하기 쉬움 |
| 빠뜨림 | 판단이 갈리는 내용은 남긴다 | 요약하다 결정사항을 날리는 게 최악 |
| 형태 | 항목이 5개 넘으면 표, 아니면 목록 | 표는 눈으로 훑기 좋지만 짧을 땐 과하다 |
| 사용자 용어 | 그대로 유지 | 표준 용어로 고치면 사용자가 자기 문서를 못 알아본다 |

## 제작 (자료·디자인·파일)

| 항목 | 기본값 | 이유 |
|---|---|---|
| 완성도 | 초안 수준으로 빠르게, 방향 확인 후 다듬기 | 방향이 틀리면 완성도가 아깝다 |
| 장수·개수 | 요청에 없으면 가장 작은 단위 하나 | 하나 보고 나머지를 정하는 게 서로 빠르다 |
| 저장 위치 | 원본이 있던 곳 옆 | 사용자가 찾기 쉬운 유일한 자리 |
| 파일명 | 원본명 + 알아볼 수 있는 접미사 | 덮어쓰기 사고 방지 |

## 결손이 남아 있으면 기본값으로 넘기지 않는 것

아래는 **기본값이 틀렸을 때 되돌릴 수 없는** 것들이라, 여기에 결손이 남아 있으면 질문 개수 제한과 상관없이 확인한다.

**결손이 없으면 확인하지 않는다.** "`temp.log` 지워줘"는 지울 대상도 범위도 선명하므로 그냥 지운다.
되돌릴 수 없다는 사실 자체가 확인 사유는 아니다 — 확인 사유는 언제나 **의도가 덜 채워졌다는 것**이고, 되돌리기 비용은 그 무게를 재는 저울일 뿐이다.

- 파일 삭제, 덮어쓰기
- 메일·메시지 발송, 외부 게시
- 결제·주문·예약
- 여러 파일을 한꺼번에 바꾸는 일괄 작업
- 남의 계정·데이터를 건드리는 일

이때 질문은 선택지가 아니라 예/아니오로 낸다. "원본 `보고서.docx`를 덮어씁니다. 진행할까요? (원본을 남기려면 말씀해 주세요)"
