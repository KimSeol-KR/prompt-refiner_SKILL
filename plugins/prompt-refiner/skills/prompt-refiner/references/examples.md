# 실제 예시 — 이렇게 나오면 잘 된 것

카드 톤과 질문 만드는 감을 잡기 위한 6건. 4번은 **카드를 뒤로 미루는 경우**, 마지막 두 건은 **보정하면 안 되는 경우**다.

---

## 예시 1 — 목적이 빠진 전형

**원문**: "이거 보고서 좀 정리해줘" (회의록 3개 첨부)

**읽어낸 것**
- 확정: 첨부 회의록 3개
- 추론: 흩어진 회의 내용을 하나로 합치려는 것
- 공백: 목적(=누구에게 가는가), 분량, 무엇을 앞에 둘지

**카드**
```
이렇게 이해했어요 — 맞으면 진행할게요.

**하려는 것**: 회의록 3개를 하나의 보고 문서로 합치기
**만들 것**: A4 한 장, 결정사항 먼저 / 논의 내용 뒤
**이렇게 가정했어요**: 회의 순서대로 정리했고, 결론이 안 난 안건도 "미정"으로 남겨둘게요

확인하고 싶은 것:
1. 이 문서 어디에 쓰세요?
   A) 팀장님 보고 — 결정사항과 다음 할 일 위주로 압축
   B) 팀 공유 — 논의 맥락까지 남겨서 나중에 찾아보기 좋게
   C) 나만 볼 정리 — 형식 신경 안 쓰고 내용 위주로

"그냥 진행"이라고 하시면 위 가정대로 바로 만들게요.
```

**왜 이렇게**: 질문 하나(목적)로 분량·톤·강조점이 한꺼번에 정해진다. 나머지는 다 가정으로 넘겼다.

## 예시 2 — 판단 기준이 빠진 경우

**원문**: "노트북 좋은 거 몇 개 추천해줘"

**공백**: "좋은"의 기준, 예산, 용도

**카드**
```
이렇게 이해했어요 — 맞으면 진행할게요.

**하려는 것**: 조건에 맞는 노트북 3~4개 추려서 비교해 드리기
**만들 것**: 표 하나 (모델 / 가격 / 장점 / 단점)
**이렇게 가정했어요**: 지금 파는 신제품 위주로 보고, 가격은 확인한 날짜와 함께 적을게요

확인하고 싶은 것:
1. 주로 뭐 하실 건가요?
   A) 문서·웹 위주 — 가볍고 배터리 오래 가는 쪽
   B) 영상 편집·개발 — 성능 위주, 무겁고 비쌈
   C) 게임 — 그래픽 위주
2. 예산은 어느 정도로 볼까요? (대략만 알려주셔도 돼요)

"그냥 진행"이라고 하시면 100만 원대 문서용 기준으로 볼게요.
```

**왜 이렇게**: "좋은 거"는 용도 없이는 아무 의미가 없다. 예산은 대략만 있어도 후보가 확 줄어서 물을 값어치가 있다. 탈출구에 구체적 기본값을 박아둔 것도 포인트 — "그냥 진행"을 눌러도 결과가 나온다.

## 예시 3 — 되돌릴 수 없는 작업

**원문**: "다운로드에 있는 사진들 파일명 정리해줘"

**공백**: 어떤 규칙으로, 원본 유지 여부

**카드**
```
Downloads에서 사진 파일 48개를 찾았어요. 이름을 바꾸기 전에 두 가지만 확인할게요.

**하려는 것**: 사진 48개 파일명을 알아보기 쉽게 통일
**이렇게 가정했어요**: `2026-08-27_001.jpg` 식으로 찍은 날짜 + 순번을 쓸게요

확인하고 싶은 것:
1. 원본은 어떻게 할까요?
   A) 이름만 바꾸기 — 원래 이름은 사라져요
   B) 복사본을 새 폴더에 만들기 — 원본 그대로 두고 정리된 사본을 받아요 (추천)
```

**왜 이렇게**: "정리해줘"에는 이름 규칙도 원본 처리도 안 적혀 있다 — **결손이 둘**이고, 그 둘이 틀리면 48개 파일의 원래 이름이 사라진다. 되돌리기 비용이 결손의 무게를 키운 경우라 질문 개수 제한과 무관하게 원본 처리를 확인한다.
반대로 "사진들 이름 앞에 `2026_` 붙여줘"였다면 규칙이 선명하므로 묻지 않고 바로 한다. **되돌릴 수 없다는 사실만으로 확인하는 것이 아니다.**
그리고 파일 목록은 **묻지 않고 직접 찾아서** 개수까지 확인시켜 줬다 — 찾을 수 있는 건 묻지 않는다.

## 예시 4 — 재료를 못 봤을 때 (카드를 뒤로 미룸)

**원문**: "저 밑에 지도 누르면 공고가 딱 나오는데 구분돼서 나오게 해봐"

**먼저 한 일**: 질문을 만들기 전에 연결된 폴더를 확인 → 연결된 폴더 없음. 코드를 볼 방법이 없다는 걸 **묻기 전에** 확인했다.

**읽어낸 것**
- 확정: 지도, 공고, 눌렀을 때 뜨는 목록
- 공백: (a) "구분돼서"가 무슨 뜻인지 — 해석에 따라 코드가 완전히 갈림 (b) 대상 코드

**행동**: 카드 없이 질문 2개만. 코드를 못 봤으니 "만들 것"과 "가정"을 쓸 수 없다.

```
1. "구분돼서"가 어느 쪽인가요?
   A) 종류별로 묶어서 — 업종·시급 같은 기준으로 그룹 나눠서 제목 밑에 목록
   B) 칸이 나뉘어 보이게 — 지금 붙어 있으니 카드처럼 하나씩 떨어지게
   C) 겹친 공고가 따로 보이게 — 같은 위치에 여러 개일 때 각각 보이게

2. 코드를 어떻게 볼까요? (지금 폴더 연결이 안 돼 있어서 파일을 못 봅니다)
   A) 목록 그리는 부분만 붙여넣기  B) 프로젝트 폴더 연결  C) 일단 예시 틀만
```

**그리고 결과물 뒤에 가정을 붙였다**

```
**이렇게 가정하고 넣었어요** — 다르면 말씀해주세요.
- 그룹 안 정렬은 가까운 순 (지도에서 들어온 맥락이라 거리를 우선으로 봤어요)
- 그룹 순서는 고정 배열 우선, 나머지는 개수 많은 순 (매번 바뀌면 눈으로 못 찾아서요)
- 접기 없이 다 펼침 (한 마커에 20건씩 쌓이면 그때 접기가 필요해집니다)
```

**왜 이렇게**: "구분돼서"의 세 해석은 각각 완전히 다른 코드로 간다. 여기서 안 물었으면 재작업이 확정이었다.
반대로 정렬 순서 같은 건 물을 값어치가 없다 — 만들어 놓고 보면 사용자가 1초 만에 판단한다. **실물을 놓고 고치는 게 말로 정하는 것보다 쉬운 항목은 사후로 미룬다.**

## 예시 5 — 보정하지 않는 경우 (이미 구체적)

**원문**: "이 CSV에서 매출 열이랑 원가 열로 이익률 계산해서 새 열 추가하고 저장해줘"

**판단**: 재료·작업·산출물이 다 있다. 공백은 소수점 자리수 정도인데 이건 만들고 나서 고치면 되는 것.

**행동**: 카드 없이 바로 실행. 끝에 한 줄만 덧붙인다.

> 이익률 열을 추가해서 저장했어요. 소수점 첫째 자리로 반올림했는데, 다르게 원하시면 말씀해 주세요.

**왜 이렇게**: 여기서 확인 카드를 띄우면 사용자는 "왜 물어봐, 그냥 하면 되잖아"라고 느낀다. **보정하지 않는 판단도 이 스킬의 일부다.**

## 예시 6 — 보정하지 않는 경우 (가볍고 되돌리기 쉬움)

**원문**: "이 문장 좀 자연스럽게 다듬어줘" (문장 한 줄 첨부)

**판단**: 결손은 있다(말투? 어디에 쓸 글?). 하지만 결과물이 한 줄이라 그냥 만들어 보여주는 게 묻는 것보다 빠르다.

**행동**: 두세 가지 버전을 바로 내놓는다.

> 세 가지로 다듬어 봤어요.
> - 부드럽게: …
> - 간결하게: …
> - 격식 있게: …
> 쓰실 곳 알려주시면 그쪽에 맞춰 더 손볼게요.

**왜 이렇게**: 선택지를 **질문으로** 주는 대신 **결과물로** 줬다. 가벼운 작업에서는 이게 마찰이 훨씬 적다.
질문을 던지는 것만이 의도 확인은 아니다.
